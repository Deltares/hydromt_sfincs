API#

SFINCS Model class#

The hydromt_sfincs.SfincsModel class is the main entry point to read, write, build, and update SFINCS models using HydroMT. It uses the functionalities provided by the reusable components defined in the hydromt_sfincs.components module.

Grid#

The regular-grid component’s data property contains the complete gridded dataset. The individual grid components (for example, elevation, mask, and roughness) also provide a data property, but that property exposes only the layer or layers relevant to that component. These are component-specific views of data stored on the shared grid; they are not separate data stores. To add or replace a layer, use the parent grid’s set() method.

The grid reads and writes the cell index, mask, and elevation maps. Other component-owned maps are read and written by their components through the grid’s internal layer I/O methods. When SfincsGrid.write() is called with write_components=True, it also calls the owning components’ write() methods. Regular-grid infiltration layers are stored in their configured binary map files; subgrid tables are managed by the subgrid component.

Quadtree#

The quadtree grid’s data property contains the complete mesh dataset. Individual quadtree components expose their relevant layer or layers through their own data properties. These are component-specific views of data stored on the shared quadtree grid, not separate data stores; use the parent grid’s set() method to add or replace a layer. The component views retain the mesh topology.

The mask, elevation, and any quadtree-specific variables are stored in the main quadtree file (qtrfile). Other component-owned variables are written to standalone UGRID netCDF files by their components. Calling SfincsQuadtreeGrid.write() with write_components=True also invokes those component writers. Quadtree infiltration, including bucket variables, is stored in inffile; inftype identifies the flavor. The subgrid table is managed separately by its subgrid component.
